# SOCAI v5: LLM viết SQL, nhiều mẫu bỏ phiếu (13/11/2026)

> Bản viết mới, **không dùng code v4** và **không nhìn dữ liệu public** khi thiết kế. Chỉ dùng lại các module nền viết từ thời train: `socai.io` (đọc ô, đọc file), `socai.profile.readme`, `socai.rules.timeexpr`, `socai.rules.calendar`, `socai.eval.scorer`, `socai.llm`.
> **Trạng thái: chưa đo trên dữ liệu thật và chưa chạy với LLM thật.** 10 test trong `tests/test_v5.py` chạy trên dữ liệu tổng hợp với LLM giả. Mặc định của `predict.sh` vẫn là v2.

## 1. Ý tưởng
Không có logic riêng cho shop hay ngành nào. Code chỉ làm ba việc: đưa dữ liệu vào DuckDB cho sạch, đưa cho LLM đúng phần schema + luật + ví dụ cần cho câu hỏi, và quyết định có trả lời hay không. LLM viết **một câu SQL** cho mỗi mẫu; DuckDB tính. Mỗi câu hỏi lấy nhiều mẫu rồi bỏ phiếu trên đáp án đã định dạng. Mức đồng thuận quyết định trả lời hay bỏ trống.

## 2. Sáu tầng
| Tầng | File | Vào → ra |
|---|---|---|
| L1 Đọc | `l1_read.py` | file CSV/XLSX/SQLite + README → bảng đã ép kiểu (số, số lượng, ngày, giờ, chữ), bỏ dòng tiêu đề lặp và dòng tổng, điền nhóm ô gộp. Mỗi quyết định ghi vào `notes` |
| L2 Mô hình dữ liệu | `l2_model.py` | bảng → DuckDB + hồ sơ cột (giá trị liệt kê, min/max, mẫu) + chỉ mục giá trị không dấu + khoảng ngày dữ liệu + ngành. Macro SQL `khoa(x)` so khớp chữ không dấu |
| L3 Luật | `l3_rules.py` | `rulebook.md` **của chính split đang chạy** → thẻ luật, truy hồi BM25 theo câu hỏi, ưu tiên ngành của shop, loại thẻ ngành khác |
| L4 Hỏi | `l4_ask.py` | câu hỏi → kỳ thời gian (`timeexpr`), thực thể khớp trong chỉ mục giá trị, bảng liên quan, luật, ví dụ → prompt. LLM trả JSON `{nghi, loai, don_vi, sql}` theo schema đóng |
| L5 Tính | `l5_compute.py` | chạy đúng một câu SELECT (có giới hạn thời gian và số dòng), định dạng đáp án theo loại; lỗi SQL hoặc sai hình dạng thì trả lỗi cho LLM sửa một lần |
| L6 Quyết định | `l6_decide.py` | các mẫu → nhóm đồng thuận → xác suất đúng của nhóm (`calibration.json`) → trả lời khi p > 0,5, ngược lại bỏ trống. Cổng thời gian: kỳ hỏi nằm ngoài dữ liệu thì `unanswerable` |

`pipeline.py` ghép sáu tầng: mỗi URL LLM một luồng, ngân sách thời gian tự giảm số mẫu mỗi câu khi sắp hết giờ, ghi `submission.jsonl`, `logs/log.jsonl` (id, answer, elapsed_ms, thinking, code, output), `logs/shops.jsonl`, `logs/run_summary.json`. `bank.py` giữ SQL của các mẫu đã chấm đúng **trên train** làm ví dụ.

## 3. Chạy
```bash
pip install -e ".[dev]" && pytest -q tests/test_v5.py
python -m socai.v5 shop --data ../train --shop biz_101          # xem L1 + L2 đọc shop ra sao, không cần LLM
python -m socai.v5 predict --data ../train --out runs/v5 --llm http://127.0.0.1:8088/v1 \
    --shops biz_101,biz_102 --limit 20 --bank-exclude-own
python -m socai.v5 eval --pred runs/v5/submission.jsonl --ref ../train/answers.jsonl --questions ../train/questions.jsonl
```
Laptop (Qwen3-4B, một server): thêm `--samples 2` cho nhanh. Kaggle 2×T4 (Qwen3-14B): `kaggle/run_v5.py`.

## 4. Quy trình đo và dựng ngân hàng ví dụ (không cần thuê máy)
1. Kaggle, `V5_SHOPS=dev V5_BUILD=1 V5_LIMIT=0`: chạy 24 shop dev, rồi tự dựng `bank.json` (ví dụ đã kiểm chứng) và `calibration.json` (xác suất đúng theo nhóm đồng thuận).
2. Cùng phiên, `V5_SHOPS=holdout`: đo 6 shop hold-out có ngân hàng ví dụ. Đây là con số để so với v2 (0,808 với 14B trên 120 câu).
3. Tải `bank.json`, `calibration.json` về, đặt vào `src/socai/v5/` trước khi build Docker. `bank.json` chứa câu hỏi train nên bị gitignore; phải có mặt lúc `docker build`.
4. Chỉ chuyển Docker sang v5 (`SOCAI_PIPELINE=v5`) khi hold-out của v5 cao hơn v2 rõ ràng.

Thời gian: v2 đo ~10,5 giây/câu với 14B trên T4. v5 gọi LLM 4 lần mỗi câu nên chậm hơn khoảng 3–4 lần trên Kaggle; 24 shop dev có thể phải chia hai phiên (dùng `V5_SHOPS=biz_…`).

## 5. Docker
`SOCAI_PIPELINE=v5 bash predict.sh`: mỗi GPU một server vLLM (cổng 8000, 8001), v5 chia câu hỏi cho hai server. `SOCAI_SAMPLES` đổi số mẫu (mặc định 4). Ngân sách 5 giờ 24 phút tính từ lúc script bắt đầu.

## 6. Chưa kiểm chứng
- PA trên dữ liệu thật: chưa có số nào.
- vLLM có nhận `response_format: json_schema` giống llama.cpp không, và mẫu có nhiệt độ + seed cố định có tái lập trong 0,03 PA không (Rule 8): phải thử khi build Docker.
- `calibration.json` chưa có thì dùng xác suất mặc định trong `l6_decide.DEFAULT_P`, là số ước lượng, chưa đo.
- Tổng tham số: v5 chỉ dùng một LLM, không có mô hình phụ.
