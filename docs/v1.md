# SổCái v1: đường luật + Qwen3-4B tách câu thành kế hoạch (10–11/11)

> Phần chung (đề bài, dữ liệu, hạ tầng): [chung.md](chung.md). Bản kế nhiệm: [v2.md](v2.md).
> Trạng thái: đường luật v1 **vẫn chạy trước** trong v2. Đường kế hoạch (`use_plan`) bị thay bằng v2, mã vẫn còn trong repo.

## 1. Ý tưởng
- **Đường luật (fastpath):** regex nhận 8 ý định (doanh thu, số đơn, huỷ, tăng trưởng, ngày cao điểm…) rồi gọi metric tất định trong `exec/metrics.py`. Mỗi metric ghi rõ § rulebook. Câu nào có bộ lọc chưa hỗ trợ thì bị chặn.
- **Qwen3-4B làm "người đọc câu hỏi", code làm "người tính":** LLM điền JSON `{metric, tên được nhắc, top_k…}` từ danh sách loại chỉ số có mô tả (`nlq/plan.py`).
- **Code thực hiện:** neo tên vào danh mục thật của shop (`semantic/entities.py`; khớp đúng một mục mới dùng), rồi chạy lệnh cơ bản lọc/nhóm/top/tỉ trọng/so kỳ (`exec/query.py`).
- **Chính sách:** trả lời khi p̂ > ngưỡng. Đường luật và kế hoạch mâu thuẫn nhau thì bỏ trống.

```
câu hỏi → chuẩn hoá → [A] regex ──────────────┐
                    → [B] 4B → JSON kế hoạch → tra tên → lệnh cơ bản → [E] chính sách → đáp án / bỏ trống
thời gian → code tất định ─────────────────────┘
```

## 2. Vì sao chọn hướng này: đo trên laptop 4 GB [ĐCBC, mẫu nhỏ]
| Thử | Kết quả |
|---|---|
| 4B tự viết code pandas (23 câu đường luật bỏ qua) | **0/23**: bịa tên cột, logic sai; mất 19–70 giây/câu |
| 4B chỉ chọn loại chỉ số + chép tên (20 câu) | **17/20** đúng loại, 0,6–1,2 giây/câu |
| Prompt kiểu cũ (toàn văn rulebook + hồ sơ shop) | 8.000–10.500 token, không vừa 4 GB |

Kết luận: bỏ hướng "LLM viết code tự do" và bỏ rulebook khỏi prompt; luật được áp trong code metric.

## 3. Kết quả
**Đường luật một mình, 3.000 câu train:** PA từ +0,023 lên **+0,295** (939 đúng, 54 sai, 2.007 bỏ trống; precision 94,6%). Các bước làm tăng điểm:
- chặn câu có bộ lọc chưa hỗ trợ;
- bỏ dòng tổng chèn giữa sổ (biz_130 doanh thu ×3);
- gỡ Telex sót;
- đọc `1,156tr`/`1tr590`, từ chối khi còn ô tiền lỗi (biz_129 ×40, biz_127 thiếu 8%);
- sửa lỗi hiểu "cùng kỳ năm trước" thành "kỳ trước".

Số này lạc quan, vì regex được viết khi đã nhìn lỗi của chính các câu train đó.

**Hold-out 6 shop (631 câu):**
| Cấu hình | Đúng | Sai | Bỏ trống | PA |
|---|---|---|---|---|
| Chỉ đường luật | 142 | 2 | 487 | 0,222 |
| Luật + kế hoạch 4B (10/11) | 239 | 66 | 326 | 0,274 |
| + bảng chuẩn mới + ngưỡng hiệu chỉnh (11/11) | 289 | 69 | 273 | **0,349** |

## 4. Giới hạn dẫn tới v2
v1 liệt kê `measure × shape`: mỗi loại câu mới cần một nhánh code, cộng thêm các "vá" trong `nlq/plan.py::to_spec`. Đo trên 3.000 câu train:

| Nhóm câu | Số câu | v1 |
|---|---|---|
| Công nợ | 117 | bỏ trống hết |
| Nhập hàng | 114 | bỏ trống hết |
| Giá bán | ~190 | 113 bỏ trống, 35 sai |
| Kê đơn / hoạt chất | 85 | bỏ trống hết |
| Ngưỡng ("từ 5 đơn trở lên") | 82 | 59 bỏ trống, 21 sai |
| Ca sáng / chiều | 77 | 38 sai (bộ lọc ca bị bỏ qua) |

Phần lớn các nhóm này chỉ là **cùng vài phép tính trên cột khác, bảng khác**. Điểm v1 bị giới hạn bởi độ phủ của thư viện metric chứ không phải bởi mô hình, và ngành mới ở private sẽ rơi ra ngoài thư viện.
